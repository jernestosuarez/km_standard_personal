# Documentation guide

This directory supports two ways into the Glassity Edition without creating a second source of
truth for the Standard.

## Start here

- **Adopting the Standard:** [`adopting.md`](adopting.md)
- **Maintaining this edition:** [`maintaining.md`](maintaining.md)
- **Onboarding a vault into an estate:** [`vault-onboarding.md`](vault-onboarding.md)
- **Normative requirements:** [`../STANDARD.md`](../STANDARD.md)
- **License and reuse:** [`license-and-reuse.md`](license-and-reuse.md)

## Architecture

[`../STANDARD.md`](../STANDARD.md) is the current and normative architecture. The material in
[`architecture/`](architecture/README.md) is a historical snapshot of v1.22. It is useful for
understanding the earlier layer model, but it does not describe later capabilities and must not be
used as the current contract.

## Design and change records

- [`../rfcs/README.md`](../rfcs/README.md) indexes dated RFCs and their adoption status.
- [`../openspec/`](../openspec/) contains governed change proposals and supporting evidence.
- [`superpowers/specs/`](superpowers/specs/) records approved repository-level designs.
- [`superpowers/plans/`](superpowers/plans/) records implementation plans.

Descriptive guidance may explain the system, but it cannot override the normative Standard.
