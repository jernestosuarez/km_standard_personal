# Skill: km-gather — Research Sources and Propose Hub Updates

You have been invoked as `/km-gather`. Search one or more sources, compare against the full
current hub state, and produce a sourced proposal for hub updates. Every proposed change must
be traceable to a specific source, locator, and evidence excerpt.

---

## Step 1 — Read source configuration

Read `sources.config.md` from the hub root.

Show the user the available sources:
- **Universal** (always available): files, folder, paste
- **Configured** (listed under "## Configured sources"): any MCP tools or adapters declared there

Ask: **"Do you want to add or update a source before we start?"**

- **Yes** → collect: source name, type, tool/method name, description → append a new entry under
  "## Configured sources" in `sources.config.md`, updating the `_Last updated_` line → confirm → proceed
- **No** → proceed

If `sources.config.md` does not exist, create it with the universal types only and ask the same question.

---

## Step 2 — Load hub context (required before any gathering)

Read ALL of the following in full:

- Every numbered hub doc present: `01_*.md` through `10_*.md`
- All `reconciliation/*.md` topic files, excluding `README.md` (settled facts)

Build a complete internal model of what this hub currently knows: facts, decisions, dates,
statuses, relationships, open items. **Do not proceed to Step 3 until every file is read.**
This step exists so gap analysis in Step 5 is grounded — not a guess.

---

## Step 3 — Collect search inputs

Ask the user in one message:

1. **Which source(s) to use** — pick from the menu in Step 1 (can be more than one)
2. **What to look for** — topic, query, keywords, or date range (ask what's appropriate per source type)
3. **Which hub docs to focus on** — optional; default is all

---

## Step 4 — Extract from sources

Read or search each selected source. As you extract, tag every fact as a tuple:

```
(claim, source_name, locator, evidence)
```

- **source_name** — as declared in sources.config.md or provided by the user
- **locator** — the most specific reference available: file path + line/page, MCP page ID, timestamp, date, section heading
- **evidence** — a direct quote or close paraphrase from the source (max 2 sentences)

**Hard rule:** if a fact cannot be pinned to a specific locator and evidence excerpt, do not include
it in the proposal. Flag it to the user at Step 8 as "could not be sourced."

---

## Step 5 — Gap analysis

Compare each extracted fact against the hub context loaded in Step 2.

Keep only facts that are:
- **New** — not captured anywhere in the current hub docs
- **Changed** — contradicting or meaningfully updating something already in the hub

Discard facts the hub already covers well. If a fact is borderline (hub has something related but not
this specific detail), keep it and note the relationship in the proposal.

---

## Step 6 — Reconciliation check

For each fact that survived gap analysis:

- Check against all `reconciliation/*.md` settled facts, excluding `README.md`
- **No conflict** → proceed
- **Conflict** → do NOT include the change in the proposal body; instead add a
  `⚠ RECONCILIATION CONFLICT` block at the top of the proposal file listing the clash and
  which settled fact it contradicts (by ID). Hub owner decision required before this change can be applied.

---

## Step 7 — Write proposal

If no facts survived Steps 5–6, tell the user "nothing new found — no proposal created" and stop.

Otherwise create `changes/YYYY-MM-DD_agent_<slug>_proposal.md`:

```markdown
# Proposal — [slug] ([YYYY-MM-DD])

**Generated by:** /km-gather
**Hub docs read:** [list every doc read in Step 2]

**Sources searched:**
- [Source name] — [locator or query used]
- [Source name] — [locator or query used]

**Reconciliation conflicts:** [none] OR [list — see conflicts block below]

---

<!-- Only present if Step 6 found conflicts -->
## ⚠ Reconciliation conflicts — hub owner decision required

| Conflict | Incoming claim | Settled fact (ID) |
|---|---|---|
| [topic] | [what the source says] | [reconciliation ID + value] |

---

## Proposed changes

### [hub-doc-filename.md] — [one-line description]

**Source:** [source name] → [locator]
**Evidence:** > "[direct quote or close paraphrase from source]"
**Change:** [exact text to add or update, or precise instruction for the agent applying this proposal]

---

### [next-hub-doc.md] — [one-line description]

**Source:** [source name] → [locator]
**Evidence:** > "[quote]"
**Change:** [instruction]
```

---

## Step 8 — Report to user

Summarise in this order:
- Sources searched (list)
- Facts extracted: N total
- Kept (new or changed): N
- Discarded (already in hub): N
- Flagged (no locator/evidence): N — list them
- Reconciliation conflicts: N — list if any
- Proposal: `changes/[filename]` created, OR "no proposal — nothing new found"

Remind the user: to apply the proposal, create a matching approval file in `changes/` or confirm
approval in chat — the agent will then apply all changes, delete both files, and commit them.
